# SAFE/startup compatibility with current main, October 21, 2026

Lead amendment while integration_lock is held by Codex lead. Current main now contains reviewed INPUT-02 and monitor corrections. STARTUP-WINDOW-01 is stacked on independently reviewed SAFE; synchronizing that stack exposed one controller merge conflict involving SAFE's shared command registry/validation and INPUT's scoped chord/hold rules. This amendment authorizes only the necessary combined-tree compatibility work before independent confirmation. The geometry contract and public recovery/command APIs are unchanged.

- Move current main's exact command entries, IDs, defaults, scopes, repeat and hold flags into SAFE's existing central command_registry.cpp. Keep one shipped definition and its existing public span/resolve API. No command is added or rebound by this migration.
- Private binding_validation.hpp becomes the common INPUT-aware rule: at most two steps, Escape reserved, holds single-key, overlapping scopes/prefixes conflict, disjoint pane scopes can reuse a sequence. Unknown IDs keep conservative global overlap. GUI and headless selected-binding restore must use this same rule, including user choices winning over conflicting newly introduced defaults.
- Preserve SAFE's asynchronous per-binding writer, rollback and foreign-change merge behavior. Use scoped collision checks both before admission and under the writer lock.
- Treat INPUT wheelModifiers ctrl/shift/alt as known viewing fields, accepting navigate/zoom/pan/pan-horizontal. Preserve unknown modifier keys and other unrelated settings. Omitted known fields follow existing selected-section removal/default semantics. Advance the known-field policy revision marker so previews from the former policy are stale.
- Move new per-modifier GUI edits onto SAFE's existing bounded, value-owned saveWithRetry channel per modifier. Preserve foreign/unknown modifier entries, latest-value semantics and lifetime-safe completion. Loading defaults after removal/reset must not retain a stale modifier value.
- Lead makes startup production/test wiring unconditional on the synchronized candidate. No renderer, decoder, QML, timeout, frame/RGB oracle or 35-command verifier changes are authorized.

Validation must cover disjoint and overlapping scoped binding restores, hold/chord rejection, viewer/recovery consistency, modifier preservation/default removal/invalid values, and modifier edits under a held checkpoint lease. Use existing dedicated recovery tests and INPUT/slot tests. The candidate needs actual independent Sonnet review of this compatibility delta and the complete combined source, then full locked Windows/Docker gates with mandatory geometry target before any main product merge. A service quota does not count as acceptance.

## 1. Decisions

- **Independent tracks, not waves.** Six tracks with disjoint hot-file ownership run concurrently in cloud sessions. The takeover's wave order is only a priority tie-breaker inside a track.
- **Enablement first.** One short phase removes the structural causes of merge conflicts and slow verification before feature tracks start.
- **The CI gate decides done.** `lead-windows-gate` (self-hosted runner on the user's PC: full Windows suite, then the Docker build, under the machine lock) is the single authoritative gate for every integration. Nobody hand-runs `scripts/build.ps1 -Test` as integration evidence. `hosted-windows` is advisory: an early warning that never marks anything done; a failure seen only there is triaged against the PC job before anyone acts.
- **Parent host.** Because the gate is CI, the parent can run locally or in the cloud with the same procedure. Run it locally when the user is at the machine (AgentMemory, worktree hygiene, runner restarts, hardware runbooks), in the cloud otherwise. A gate queued while the PC is off is reported as pending; the parent keeps working on other packets.
- **Physical hardware qualification** becomes RUNBOOK packets: agents produce runbooks, fixtures and result templates; the user runs them; the parent records the evidence. CANVAS-UI, DECODE-01 and MONITOR-VERIFY-01 stay `integration`/`unverified` until then. No headless result is relabeled as physical.

## 3. Operating model

### Roles

| Role | Where | Count | Does |
| --- | --- | --- | --- |
| **Parent** (Opus 5.5) | Windows machine or cloud | 1 | Contract commits, queue, root CMake, shared headers, integration batches, `gate/*` pushes, evidence, AgentMemory, worktree hygiene, runbook hand-off to the user. Implements nothing else. |
| **Track session** (Opus 5.5) | Cloud, one per track | 5–6 | Owns one track's branches. Spawns implementer subagents (one per packet, at most two compiling at once), runs targeted and full offscreen `ctest`, writes handoffs. Never edits root CMake, the queue or another track's files. |
| **Review session** (Opus 5.5) | Cloud | 1–2 | Spawns fresh-context reviewers for other tracks' packets: read-only worktree, pinned `git diff <contract SHA> <tip SHA>`, `docs/verification/<TASK>-REVIEW.md` with APPROVED or CHANGES REQUIRED. A track never reviews its own packets. |
| **Gate** | CI `lead-windows-gate` | serial | Decides done. |

### Packet lifecycle (states unchanged: ready → implementing → review → integration → done)

1. **Contract commit** (parent, on `main`): shared headers, `cmake/<Feature>Tests.cmake` plus its `include()`, an empty per-task block in `src/app/command_registry.cpp`, `docs/<TASK>-PLAN.md`, the queue row. Commit `chore(lead): freeze <track>-<n> contracts`.
2. **Implement** (track session): branch `claude/<task>` from the contract SHA, worktree `.worktrees/claude-<task>`, build `build-claude-<task>`. Tests in `tests/<feature>_tests.cpp` or `tests/<feature>_ui_tests.cpp`. UI packets load the ui-design-skills before QML edits. Handoff `docs/handoff/<TASK>-HANDOFF.md` with actual `ctest` output: targeted, then `ctest -L fast`, then one full suite.
3. **Review** (review session): fresh subagent. Fixes return to the implementer; a new fresh reviewer re-reviews.
4. **Integrate** (parent, serial): set `integration_lock`; merge `main` into the branch, or batch two to four approved packets into `lead/integrate-<track>-<n>`; push the exact commit as `gate/<track>-<n>`; wait for `lead-windows-gate` to pass; merge `--no-ff`; `docs: qualify <packet> integration` evidence commit with the run URL, summary and downloaded logs; update the queue; clear the lock; fast-forward push `main`; delete the `gate/*` branch. A failing packet is pulled from the batch and returned.
5. **Done** only after independent review and a passing gate on the integrated commit. Hardware rows stay unverified unless measured.

### Gate budget

One gate is about 13 minutes of Windows tests plus about 18 of Docker, so 30–35 minutes wall clock in a temporary worktree under the machine lock. One runner runs one job, so requests queue. Rules: batch two to four approved packets per gate; nothing heavy on the Windows machine while a gate runs (no local full gates, no targeted `folder_grid`, `fs_watch_budget` or clipboard UI tests); keep Docker Desktop running; cloud sessions pre-qualify with a full offscreen `ctest`; a manual run may skip Docker only for triage, never for integration evidence. Expect 60–80 packets, 20–40 gates, roughly 10–25 hours of runner time in total.

### Concurrency limits

- Cloud: about 2 GB RAM per compile job; at most two compiling subagents per session plus read-only reviewers; one full `ctest` at a time per session. The budget tests (`fs_watch_budget`, `fs_watch`, `folder_grid`, `cache`, `window_slots`, `recovery_controller`, `input_ui`) may flake under cloud load: rerun once, record both results; the Windows gate is the authority.
- Windows machine: nothing heavy while the runner is gating.

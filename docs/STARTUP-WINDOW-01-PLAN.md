## Required behavior

- A startup window entirely outside all usable available-screen rectangles must be recovered before the timed viewing interval. Apply the recovery after Qt has supplied actual geometry/screens and before the quit timer/replay starts. Do not extend the viewing interval to wait for an expose, synthesize expose events or make screenshot-only rendering pass.
- Preserve valid partially/fully onscreen geometry. Only positive-area intersection with a usable rectangle qualifies as visible for this value decision; touching edges do not. Do not move a legitimate user placement on another screen. No startup fullscreen/maximized policy changes.
- For an offscreen/invalid current rectangle, choose the usable preferred screen, otherwise the first usable screen in stable input order. Clamp the recovered size to available space while preserving the actual window minimum size; when a work area is smaller than that minimum, anchor the title/control area inside it rather than shrinking controls below their minimum. Center where the recovered window fits. Do not bridge monitor gaps or interpret native pixels as logical coordinates. Avoid integer overflow with checked/widened edge/center arithmetic.
- Empty/invalid screen sets return NoUsableScreen and unchanged geometry; more than64 inputs return TooManyScreens and unchanged geometry. The helper performs no allocation, GUI or I/O work and returns a bounded value result. The adapter gathers only bounded rectangles and handles diagnostic statuses explicitly, without corrupting settings.
- Preserve normal and safe startup, explicit file/no-resume behavior, existing --window-size meaning for size constraints, original settings/media bytes, per-slot recovery semantics and later legitimate window movement. Safe mode must recover without persisted geometry/settings writes.
- Add bounded additive report evidence: window x/y and pre-grab geometry/exposure/RHI/frame state, including available work-area bounds sufficient to diagnose future placement failures. Snapshot live-render evidence before grabWindow; keep the existing post-grab fields compatible and retain separate actual-swap/RGB requirements. No secrets or user media in diagnostics.
- Use relevant application-interface-design, component-geometry and responsive-layout guidance adapted to native Qt; preserve existing theme tokens and minimum controls. No web framework, restyling or QML hot-file work. Read design-review if the implementation expands into substantial UI behavior; return that scope expansion to the lead.

1. **P1: Linux commit can overwrite a newly created destination with overwrite disabled** (`src/core/selection_export.cpp:545`). The early existence check is separated from a replacing POSIX rename. A progress callback creating the previously absent destination reproduces Written while destroying its original contents, even with `overwrite=false`. Publish with an atomic no-replace operation when overwrite is disabled, preserving a concurrently created destination. Add a deterministic regression using the callback hook.
2. **P1: final-item cancellation still publishes and replaces an existing destination** (`src/core/selection_export.cpp:354`, `:512`). Cancellation is checked before invoking progress, with no check after that callback or before commit. A one-item export whose callback requests cancellation at done=0, or at completion, returns Written and replaces the original destination on both Windows and Linux. Check cancellation after callbacks and before commit; remove the temp and preserve the destination. The same one-item export calls progress twice, contrary to the packet's once-per-item bound; fix and test that bound as well.
3. **P2: Unicode destination fails on Windows** (`src/core/selection_export.cpp:286`). Converting the native wide destination filename with `.string()` throws for CJK/emoji under the tested Windows code page, before temporary output is opened. The existing Unicode test covers selected filenames but uses an ASCII destination. Generate the temporary sibling using native path strings or an ASCII-only basename independent of the destination name; cover Unicode destination names and directories without requiring a UTF-8 system locale.
4. **P2: mixed known/unknown identities bypass duplicate suppression** (`src/core/selection_export.cpp:341`, `:388`, `:504`). Known identities and unknown paths are stored in disjoint collections. With `revalidate=false`, two snapshots of the same normal path, one known identity and one `{0,0}`, are both written in either order. The contract explicitly requires lexical-path fallback when either identity is unknown. Retain enough identity/path information to enforce that rule in both orders, while preserving distinct unknown paths and identity-based hardlink deduplication.
5. **P2: relative-root computation resolves filesystem links instead of following the lexical contract** (`src/core/selection_export.cpp:147`). `fs::relative` canonicalizes paths. A lexically contained `root/alias/image.png`, with alias a symlink to an outside directory and revalidation disabled, is skipped as OutsideRoot instead of emitting `alias/image.png`. Use the frozen lexical comparison/relative-path policy, including the Windows drive-letter rule, and add a deterministic link regression on supported platforms. This finding concerns path formatting only; it does not authorize decoding or traversing link targets.

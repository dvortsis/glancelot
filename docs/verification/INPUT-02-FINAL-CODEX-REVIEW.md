## Decoder cancellation and lifetime

Inspected `src/worker/main.cpp:150-171` with parent `src/app/viewer_controller.cpp:331-341,367-417`. The worker now writes without holding the QSharedMemory system semaphore, then sends decoded and waits for acknowledgement. The parent reads only after decoded, validates geometry, copies before acknowledgement, and guards asynchronous callbacks with generation/process identity. On cancellation it disconnects/kills the worker and resets its own mapping; the attached worker retains its mapping until termination. Static protocol ordering supports removing the long-held pixel-copy semaphore and explains the reported mid-copy kill/detach deadlock. No new definite defect identified in these two changed lines.

This is **not independent cancellation proof**. Bounded kill-mid-copy, rapid image replacement, stale-result rejection, timeout/crash and teardown tests must still run on the final candidate. The worker's own attach/destructor and parent lock paths remain Qt-managed; this review does not infer all interprocess semaphore/cancellation cases from the author's observed run.

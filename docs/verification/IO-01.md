## 1. Executive Summary

Task `IO-01` delivers full compliance with requirements **PERF-05** (Storage-aware I/O concurrency) and **SYS-02** (Bounded resource usage and parser boundaries) as specified in `docs/WORK-QUEUE.yaml`, `docs/IO-01-PLAN.md`, and `docs/REQUIREMENTS.md`.

### Key Features Implemented:
1. **Storage Device Classification (`StorageDeviceType`)**:
   - Classifies file storage into `Ssd`, `Rotational` (mechanical HDD), and `Network` (SMB, CIFS, NFS).
   - Windows detection: Identifies UNC paths (`\\...`, `//...`) and `DRIVE_REMOTE` as `Network`, `DRIVE_CDROM` as `Rotational`, and queries volume seek penalty via `DeviceIoControl(IOCTL_STORAGE_QUERY_PROPERTY, StorageDeviceSeekPenaltyProperty)` where `IncursSeekPenalty == TRUE` detects HDDs.
   - Linux detection: Identifies network filesystem magic numbers (CIFS, NFS, SMB) and sysfs queue attributes (`/sys/block/<dev>/queue/rotational`).
   - Deterministic test fixtures: `setPathOverride(prefix, type)` allows automated suites to simulate SSD, HDD, and Network environments without physical disk arrays.
2. **Dynamic Concurrency & Deadlines by Storage Medium**:
   - **SSD**: Maximum concurrency (up to 2 parallel thumbnail decoder workers), 5,000 ms deadline, cross-folder lookahead prefetch enabled.
   - **Rotational (HDD)**: Serialized background I/O (clamped to 1 background worker to avoid mechanical disk seek thrashing), 8,000 ms deadline, lookahead prefetch deferred while other I/O is active.
   - **Network (SMB / CIFS / NFS)**: Conservative concurrency (clamped to 1 background worker), shortened 3,000 ms deadline for fast failure recovery on slow/unresponsive shares, speculative cross-folder lookahead prefetch suppressed to prevent remote network pipe saturation.
3. **Manual Override & Settings Persistence**:
   - Configurable storage profile (`Auto`, `SSD`, `HDD`, `Network`) with manual override commands: `storage-profile-auto`, `storage-profile-ssd`, `storage-profile-hdd`, `storage-profile-network`.
   - Persisted in `settings.json` under `storageProfile` through atomic locked configuration updates.
4. **Current-Image Priority & Memory Admission Ledger**:
   - Four priority tiers: `JobPriority::Foreground` (interactive navigation), `JobPriority::Thumbnail` (visible previews), `JobPriority::Prefetch` (lookahead), and `JobPriority::Metadata`.
   - Foreground image decodes always take priority and admit immediately, preventing background workers from locking out user interaction.
   - Combined memory ledger tracks total active bytes against the system allowance ceiling, preventing OOM exhaustion.
   - Cancellation (`cancelLookahead()`, `cancel()`, `ThumbnailService::cancel()`) immediately releases admission reservations and active slots.
5. **Integrated Test Suite (`tests/io_scheduler_tests.cpp`)**:
   - 10 targeted test cases covering storage detection, profile overrides, concurrency and deadline limits, priority admission, rotational serialization, memory budget ceiling, string helpers, `ThumbnailService` integration, `ViewerController` commands and properties, and lookahead prefetch gating.

## 4. Architectural & Safety Review

1. **Seek Contention Prevention**:
   - On mechanical hard drives, random seeks incur 10-15 ms mechanical overhead per request. Serializing thumbnail generation to a single worker and deferring speculative cross-folder lookahead until I/O settles completely eliminates the seek thrashing that otherwise freezes interactive viewing.
2. **Network Pipe Hygiene**:
   - Remote SMB/CIFS mounts incur latency and packet serialization bottlenecks. Suppressing speculative lookahead across network folders guarantees that user-requested images receive 100% of available network bandwidth.
3. **Memory Safety & Sandbox Independence**:
   - The shared admission ledger prevents runaway memory growth when viewing high-resolution folders or rapid navigation sequences.
   - Works uniformly across Windows and Linux environments.

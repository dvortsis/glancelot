Expose a `monitorCustomization` QML context property in app/main.cpp, initialized with the current viewer DisplayManager and PaneLayout, setSlot(viewer.windowSlot()), and attach the controller root window after QML creation. Follow slot changes. Do not reimplement input dispatch in a detached window: route commands through the existing registry and scope/enablement predicate, preserving text fields, dialogs, chords and held keys. Private controller/render headers may be extended within this packet; existing public DisplayManager, PaneLayout and ViewerController header changes require a lead amendment before editing. The coordinator methods return false on invalid/unsupported/locked operations and expose useful feedback; failure cannot partially change routing or persisted state. `changed` notifies all exposed maps/lists. `setSlot` rejects invalid slots and loads the same slot namespace used by the viewer. `setControllerWindow` does not take ownership. `moveOutput` preserves current presentation mode, pin, viewport and decoded image; it does not enable an inactive presentation. `swapControllerAndOutput` requires an active distinct reachable output and commits only after both effective placements are valid. `identifyDisplays` has one bounded timer (maximum3s), no focus steal, and no control widgets on clean output. `recoverToController` closes presentation, re-docks detached panes and clamps the controller into an available work area, without changing media selection or lock/freeze preferences.

`paneRoutes` contains exactly keys `tree`, `grid`, `preview`, `metadata`; each map has `detached` bool, preferred `displayId` string, `geometry` map of integer logical `x,y,width,height`, `frozen` bool, plus read-only `effectiveDisplayId` and `recovered` fields. Docked placement remains PaneLayout's responsibility. `updatePaneGeometry` records a preferred user geometry only after bounded validation; hotplug constraints must not overwrite preferred geometry. A screen fallback is not a new user preference. Geometry restoration uses the existing startup geometry helper and Qt logical coordinates, never multiplying screen origins by DPR.

`outputOptions` accepts only a validated patch with these writable keys: `displayId`, `windowMode` (`windowed|fullscreen`), `fitMode` (`shrink|fit|fill|actual`), `viewportLink` (`linked|independent`), `background` (`theme|solid|checker`), `backgroundColor` (opaque QColor-compatible #RRGGBB), `guides` bool, `imageInfo` bool, `cursorPolicy` (`auto|visible|hidden`), `followSelection` bool, `folderChange` (`follow|hold|disable`), `slideshowTiming` (`shared|independent`). Reject unknown patch keys, invalid enums, NaN, wrong types and oversized strings atomically. Read-only capability/feedback fields are separate from this writable map. Viewport controls reuse existing generation-aware output viewport commands and the controller transform model; no raw image decoding on the GUI thread. Independent timing uses at most one timer and the existing slideshow/navigation ownership model, not a second media scan. If a mode has no meaningful effect for pinned/comparison state, disable it with an explanation rather than silently changing semantics.

## Persistence and bounded ownership

Lead implementation amendment: `DisplayManager::setRoutingPolicy(const QVariantMap&)` accepts the validated followSelection/folderChange/slideshowTiming policy. Independent timing publishes the latest controller-supplied immutable image at its own bounded3s presentation cadence, using one replaceable pending frame counted against the existing retained-image budget; it never creates a second navigator/decoder. The output does not independently walk the media list. Shared timing publishes immediately. Folder hold preserves the displayed image until explicit policy change/resume; disable closes output. `paneRoutes` additionally exposes read-only `effectiveGeometry`, clamped to the current topology, while `geometry` remains the preferred placement. These additions preserve the frozen user-visible scope and remove ambiguity in the runtime bridge.

The controller viewport payload uses the existing ImageCanvas `viewState()` / `setViewState()` representation, with validation and generation checks at the coordinator boundary. This packet may expose those existing methods as Q_INVOKABLE in the private `src/render/image_canvas.hpp` and adapt its implementation for migration/physical-scale linking; no other canvas behavior or budgets may be weakened. A presentation snapshot stores the existing routing mode separately from the writable output-options patch.

Add `monitorCustomization` to the schema1 settings root, containing `version:1`, `slots` keyed by existing slot IDs. Each slot contains `output`, `panes`, `presets` and optional selected preset ID. Preset records have immutable generated `id`, trimmed display `name` (1–80 Unicode characters), `kind` (`presentation|workspace`) and validated snapshot. Empty id in savePreset creates a new ID; a nonempty id must exist and updates that record. Names compare case-insensitively within the slot and duplicates fail without mutation. Applying a preset while layout locked rejects workspace geometry edits; presentation-only changes remain possible. Preset deletion never deletes media.

Limits:64 presets/slot;16 remembered display option records/slot; IDs at most256 characters; four detached pane hosts, one controller, one existing presentation window; at most64 enumerated displays; customization subtree at most256KiB serialized and total settings retain the existing1MiB limit. Reject excess before allocation/persistence. Unknown fields and newer schemas are retained without destructive rewrite; newer customization versions use safe defaults with feedback and no automatic writeback. Preserve other slots and unrelated settings on every write. Use updateSettings/settings_retry transactions, value-owned bounded retry patches, revision/generation fencing, and explicit Busy/WriteFailed UI feedback. SAFE diff/import/reset/backup policy must recognize the new namespace as per-slot layout/output configuration; never classify it as media or replace unknown future data. Extend private recovery policy/tests as needed, with no broad settings rollback.

A workspace apply validates the entire snapshot and topology first. Stage a coherent transition, suppress intermediate persistence, then commit one settings transaction; on failure retain prior effective state or roll back to it with explicit feedback. Reuse PaneLayout's frozen snapshot extension below for restoring dock state rather than piecemeal public mutations that bypass freeze rules. At runtime keep preferred state distinct from clamped effective geometry. No restore causes display activation without an explicit user action; unavailable/ambiguous identities recover to controller. Strong serial-bearing identity can restore a preference but does not itself enable output on startup.

Presentation keeps its integrated256MiB aggregate texture admission and16MiB color reservation; source-generation and low-memory behavior remain intact. Reparent/migrate preview resources without simultaneous unbounded old/new surfaces; include detached preview resources in existing aggregate accounting. No new full-size converted raster or metadata/image decode on the GUI thread. Close/unplug/suspend/device loss destroys obsolete hosts/textures and preserves controller responsiveness. Actual unsupported Wayland positioning is reported; Docker/browser multi-output stays unsupported until separately qualified.
